# EvoMatch 用户界面设计复查

日期：2026-11-13

## 分类

HYBRID：用户任务大厅 + 独立比赛验证实验。

## 初次打开的问题

1. **首屏先展示系统内部指标，没有用户目标。** v1/v2、隐藏集、合规覆盖和签名占据了最强视觉位置，新用户不知道应该先点哪里。
2. **信息密度与字号失衡。** 大量标签和辅助文字只有 7–10px，桌面投影已经吃力，移动端不可读。
3. **三栏技术监控布局没有主次。** 任务收件箱、路由表和进化账本同时争抢注意力。
4. **任务不是一个可直接操作的对象。** 用户看不到清晰的“分配给谁、下一步做什么、为什么推荐”。
5. **比赛语言泄漏到用户路径。** “隐藏任务”“反馈学习函数”等词适合评委，不适合企业任务发布者。
6. **移动端缺少真正的布局设计。** 原页面固定最小宽度 1180px，手机必然横向溢出。
7. **缺少新任务入口。** 首屏没有搜索、快速描述或发布任务的主行动。

## 重构决定

- 默认页面改为任务大厅，首屏只保留价值说明、快速任务输入和今日概览。
- 任务列表成为主视觉，右侧详情给出执行者、理由、交付要求和明确动作。
- 新增“发布任务”和“帮我匹配”，让平台能真正产生任务并返回推荐。
- “任务进展”只显示等待验收和正在执行的工作。
- v1/v2、规则、指标、审计、回滚全部迁入“进化实验”，默认不干扰用户。
- 正文提升到 15–16px，辅助信息不低于 11–12px，按钮高度不低于 40–44px。
- 手机端使用单列任务布局，导航保持完整可见，页面无横向滚动。

## 验证

- 桌面：1440×1000 与 1280×720 已截图检查。
- 手机：CDP 390×844 设备模拟，`scrollWidth = clientWidth = 390`。
- 快速任务实测：输入“检查自动续费提示文案是否清楚，并给出修改建议”后推荐 C 合规预审，并显示高危复核提示。
- 任务动作实测：点击分配后，状态由“待分配”变为“进行中”。
- 路由引擎 7 项测试全部通过。

## 第二轮收敛

用户进一步要求参考极简浏览器首页，并明确区分“主页、任务、个人界面”。第二轮采用以下结构：

- 首页：品牌、任务输入框、五个任务类型入口、三条最近任务。
- 任务：完整任务浏览、筛选、详情和执行者建议。
- 我的：个人工作台、状态统计、待验收和进行中任务。
- 实验：比赛技术验证，不进入默认用户路径。

极简首页在 1440×1000 和 390×844 下验证完成；390px 视口 `scrollWidth = clientWidth = 390`。分类入口和快速任务提交均可进入任务页。

## 评分

面向用户的任务大厅：

- 设计：D → B
- AI 感：C → B
- 首次使用清晰度：失败 → 通过
- 移动端可用性：失败 → 通过

# TaskTok：刷到任务，交付结果

TaskTok 是一个可验收任务市场的原型。企业把需求发布成写清交付物和验收标准的任务，个人像刷短视频一样刷到与自己能力匹配的任务，认领、交付，通过验收后结算。每一次选择和验收结果都会写回平台，让下一次推荐更准。

日新主题赛道 · 黑客松项目。团队：李洋、范希言、黄崇杰、程至研。

## 命题前提

**交易单位决定计价方式。** 工作市场的交易单位已经下移过两次：职位市场卖的是岗位加一段时间，项目市场卖的是有边界的项目。TaskTok 认为下一步是可验收的任务。

**瓶颈从“找不到人”变成了“说不清什么算完成”。** 现有平台优化的是撮合，真正的成本却出在完成的判断上：

- 需求侧：“看看东南亚市场有没有机会”这样的一句话需求，没有交付物、完成标准和预算边界，没法直接定价，只能包装成岗位按时间雇人。
- 供给侧：简历和关键词是弱信号。能预测交付质量的数据（同类任务完成数、按时率、一次通过率、返工率）没有被记录下来。
- 平台侧：撮合能靠算法规模化，验收靠客服和协商，争议成本随交易量线性上涨。

**智能溢出让任务第一次可交易。** 知识工作的产出本身就是文件、表格和数据集，可以结构化描述和逐项核对；每个人都可以用自己的 AI 工具，做一份交付的成本已经很低。所以按工时定价会失真，按结果定价才合理。

**AI 是执行者自己的工具，不是平台里的角色。** 平台只和人打交道：推送给人，人来认领，人提交交付，评分也记在人身上。执行者用不用 AI、怎么用，平台不管。

完整论证见 [商业计划书](docs/TaskTok%20商业计划书：把劳动的交易单位从“岗位”移到“可验收任务”.md) 和 [产品设想](docs/IDAE.md)。

## 设计理念

**任务是一份可验收的对象。** 每个任务必须写清目标、要求、交付物、预算、截止时间、验收方式和逐条验收标准。发布表单按这几项组织，缺一项不能发布。验收时发包方逐条核对，全部满足才能通过；不通过必须写明返工原因。

**用能力记录代替简历。** 平台按任务记录每个人的完成数、按时率和各类任务的表现，形成能力图谱。推荐和排序都基于它，而不是标签和自我描述。

**推荐会从反馈中学习。** 认领、拒绝、验收结果都会更新执行者分数和七维匹配权重（技能、口碑、专长等）。权重按版本保存，可以秒级回退到任一历史版本，不覆盖历史。在严格离线评估中，worker→tasks 方向的 HR@10 从 6.37% 提升到 20.70%（+14.33pp，见 [final_summary.md](task-recommender/reports/final_summary.md)）。

**发现任务要像刷内容一样轻。** 首页是全屏的任务推荐流，上下滑切换，左滑进详情；需要精确查找时用搜索和筛选。

**界面层级清楚。** 底部五个一级页面（推荐、搜索、发布、工作台、我的）只放概览和入口，具体内容在二级页面里。返回按钮和右滑都回到上一页。进度清单只是帮执行者自己记录进度，不参与验收。

## 使用方法

### 打开应用

有两种方式，界面和操作完全一样，手机尺寸和桌面尺寸都能用：

- **直接打开**：双击 [frontend/index.html](frontend/index.html)，在 Chrome 中打开。不需要安装任何东西，数据是内置的示例数据，存在浏览器本地；想恢复初始状态，清掉 `localStorage` 里的 `tasktok-market-prototype-v3` 再刷新。
- **连同后端一起运行**：按下文“运行后端”启动后，打开 `http://127.0.0.1:8000/app/`。任务、认领、验收都走后端和数据库，推荐结果来自推荐系统。

### 接单方：找任务、做任务

1. **推荐**：上下滑浏览任务卡片，左滑或点卡片进入详情。右侧按钮可以看详情、收藏、分享和直接接单。
2. **搜索**：按关键词搜索，用筛选栏按类型、金额、发布时间、难度、验收方式筛选，面板里会实时显示结果数。
3. **认领**：在任务详情点“认领任务”。认领后等待发包方选定执行者。
4. **工作台**：按“已认领、进行中、待验收、已结束”四个标签查看自己的任务。进行中的任务可以勾选进度清单。
5. **提交**：上传交付物、写说明后提交。提交后等待发包方验收；被要求返工时，工作台会显示原因，改完重新提交。
6. **我的**：查看收入、能力图谱、收藏和浏览记录。

### 发包方：发布任务、验收

1. **发布**：在“发布”页填写任务基本信息、交付物与验收标准、预算和截止时间，发布后进入任务管理页。
2. **选定执行者**：在“我发布的任务”里打开任务，从认领者中选定一位。
3. **验收**：执行者提交后，任务显示“待你验收”。逐条核对验收标准，全部勾选才能点“验收通过并结算”；不满意就写明返工原因退回。

原型里没有第二个真实用户，两边都有虚线框的演示按钮代替对方操作：发包方在执行中的任务里点“演示：模拟执行者提交成果”进入验收；接单方在“已认领”的任务里可以模拟“发包方选定了我 / 选了别人”，在“待验收”的任务里可以模拟“验收通过 / 要求返工”。这样任意一边都能从头点到尾。

### 运行后端（可选）

推荐、反馈学习、权重回退和业务数据库在 `task-recommender/` 中，需要 Python：

```bash
cd task-recommender
python -m pip install -r requirements.txt
python -m pytest tests/ -q
python scripts/run_demo.py
```

启动后打开 `http://127.0.0.1:8000/app/`。业务数据存在 `task-recommender/data/tasktok.sqlite`，首次启动自动生成示例数据，删掉这个文件即可重置。接口和评估脚本的说明见 [task-recommender/README.md](task-recommender/README.md)。

## 适用范围

- 只覆盖数字化交付的知识型任务，例如市场研究、数据整理、内容撰写。
- 支付和结算是演示流程，没有真实资金流转。

# TaskTok

一个会从任务完成结果中学习“什么任务、在什么条件下、应该交给谁”的企业线上任务路由原型。

比赛版只覆盖中文、国内企业、可完全在线交付的内容、数据、合规、研究和产品文档任务。它不训练基础模型，不接入真实员工，也不替代律师、合规人员或企业验收责任人。

产品分为四个清晰页面：

- **首页**：只有一个任务输入框、任务类型入口和少量最近任务。
- **任务**：完整任务列表、筛选、执行者建议和任务详情。
- **我的**：个人任务进展、待验收工作和执行中的工作。
- **实验**：独立的比赛验证页面，包含 v1/v2、规则变化、隐藏任务和回滚。

```

```

## 使用方式

首页首次打开就有内容，不需要先理解版本实验：

1. 在首页输入一句话，或点击一个任务类型；
2. 进入任务页查看推荐执行者、理由和交付要求；
3. 点击“分配给执行者”“先追问发布者”或“验收交付”；
4. 在“我的”查看待验收和执行中的任务。

## 一分钟比赛演示

1. 进入“进化实验”，点击“运行 v1”；
2. 指出个人信息条款、竞品摘要和促销文案的误分；
3. 提交三条结构化纠错；
4. 生成并运行 v2，比较校准集、隐藏集和合规覆盖；
5. 回滚 v1，确认指标恢复，再恢复 v2。

也可以点击“自动预演”按同一真实按钮链路演示完整闭环。验收状态 URL：

- `?view=lab&preview=v1`
- `?view=lab&preview=v2`
- `?view=lab&preview=rollback`
- `?view=market`
- `?view=profile`

单独带 `preview` 参数不会再强制离开首页。

## 核心机制

### v1：静态标签的合理错误

v1 只使用字面关键词和通用能力：

- “检查 + 个人信息”缺少风险分类，被当成一般研究；
- “写摘要”的字面信号压过了来源核验；
- “促销文案”进入普通内容创作，没有触发合规；
- “反馈聚类”被当成封闭数据清洗。

这些选择来自同一个 v1 评分器，不是针对 `T3`、`T4`、`T6` 写死的返回结果。

### 结构化反馈

每条反馈包含：

- 正确执行者；
- 正确任务类型；
- 错误原因；
- 任务描述是否清楚；
- 下一轮修正建议。

### v2：有界、可解释的策略更新

系统只根据三条校准反馈生成四类规则：

- 任务类型重新校准；
- 公开资料核验与普通写作分离；
- 个人信息、自动续费、消费者权益、绝对化用语进入合规通道；
- 缺少检查边界时先追问。

权重更新是有界的，每条规则保留证据事件 ID 和置信度，不覆盖执行者的整体能力。

### 安全护栏

高风险任务必须包含 `C 合规预审` 和 `人工复核` 节点。v2 不会把合规初筛表述为正式法律意见。

### 回滚

每个版本运行结果生成不可变快照和确定性签名。回滚时会分别重放 v1、v2，并比较：

- v1 历史签名；
- v2 历史签名；
- 排名、规则和指标是否一致。

## 工程结构

```text
evomatch/
├─ index.html                 单页控制台
├─ styles.css                 投影与窄屏布局
├─ src/data.js                固定任务、执行者、反馈
├─ src/router-engine.js       分类、评分、学习、指标、快照
├─ src/app.js                 交互状态与页面渲染
├─ scripts/serve.mjs          零依赖静态服务器
├─ tests/router-engine.test.js
└─ deploy/evomatch.service.example
```

核心测试：

```powershell
npm test
```

测试覆盖 v1 误分、v2 校准/隐藏集指标、合规覆盖、无反馈门禁、反馈隔离、不可变快照、回滚与恢复。

## 服务器运行

把仓库放到 Linux 服务器后，可直接运行：

```bash
cd /home/agent/repos/evomatch
HOST=0.0.0.0 PORT=4173 node scripts/serve.mjs
```

需要常驻时，将 `deploy/evomatch.service.example` 复制到 `~/.config/systemd/user/evomatch.service`，再执行：

```bash
systemctl --user daemon-reload
systemctl --user enable --now evomatch
systemctl --user status evomatch
```

若使用云服务器，还需要在安全组开放实际端口，或用 Nginx/Caddy 反向代理到 `127.0.0.1:4173`。

## 已知限制

- 当前使用固定中文合成任务，不代表真实企业分布。
- 任务分类是确定性规则，适合证明学习闭环，不等于通用语义理解。
- 反馈只表达正确标签和原因，不自动扩充更多训练样本。
- v2 的迁移提升来自同一固定任务分布，仍需真实企业样本验证。
- “人工复核”是流程节点，比赛版没有实现人员登录、审批和 SLA。
- 成本、延误和验收率使用固定模拟口径，不表示真实市场价格。
